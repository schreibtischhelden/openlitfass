# Setting up an instance

An **instance** is a repository of its own for one specific calendar (for
example `weissens.ee` for Berlin-Weißensee). It contains only content and
styling, no code. The code is provided by the container image built from this
core repository.

## Directory layout

```
<instance>/
  instance.json                    required: name, title, time zone, …
  categories.json                  categories and icons (order = menu order)
  sources/*.json                   one file per source (*.example.json = template)
  inbox/*.json                     individual events added by hand (see docs/inbox.md)
  site/                            overlaid on top of web/
    css/theme.css                  overrides for the colour tokens
    logo.svg                       logo (inlined, so currentColor works;
                                   build-site derives favicon.svg from it:
                                   white on themeColor, fixed accent colour)
    icon-192.png, icon-512.png     optional: PWA and touch icons (linked only if present)
    …                              any other files (fonts, favicon, …)
  data/                            generated by fetch (events, categories, sources); committed
  public/                          generated by build-site; not committed
  .github/workflows/update-events.yml
```

## instance.json

```jsonc
{
  "name": "weissens.ee",                       // required; wordmark in the header
  "title": "weissens.ee – Events in Weißensee", // <title>; default: name
  "description": "Der Event-Kalender für …",   // <meta name="description">
  "baseUrl": "https://weissens.ee",            // public address: sitemap, canonical URL
  "timezone": "Europe/Berlin",                 // IANA time zone; default: Europe/Berlin
  "language": "de",                            // <html lang>; default: de
  "themeColor": "#17383D",                     // theme-color and PWA colours
  "shortName": "weissens.ee",                  // name below the app icon; default: name
  "about": "Paragraph 1 …\n\nParagraph 2 …",   // text of the About page
  "imprintUrl": "impressum.html",              // legal notice (mandatory in Germany)
  "privacyUrl": "datenschutz.html",            // privacy policy
  "submitUrl": "mailto:termine@weissens.ee"    // "Termin melden" (submit an event) on the About page
}
```

`imprintUrl` and `privacyUrl` may be absolute URLs or relative paths to a page
in `site/` (templates: `example-instance/site/impressum.html` and
`datenschutz.html`). A public website operated in Germany must provide a legal
notice (*Impressum*).

## Showing sources

Each source file may set `"label"` (display name) and `"homepage"` (the
organiser's website). Both are shown in the front end as "Quelle: …" (source)
in the event details and in the list of sources on the About page
(`data/sources.json`, generated by `fetch`).

## Front end

The default user interface (`web/`) provides:

- **Toolbar** below the header, acting as a summary:
  `[‹] [date] [›] … [active filters] [Filter]`. The arrows step through the
  selected period; the date opens the native date picker. The calendar starts
  on "today" and never shows earlier days. The date label shows the period,
  always as weekday and date (for example "Sa, 21.11." or "21.–27.11."), so
  that its width stays the same while paging. Active filters appear as small
  icons (tapping one removes the filter); the Filter button shows how many are
  active and opens the filter panel. If the toolbar runs out of space, the
  icons are hidden first.
- **Filter panel** with groups: period (day, weekend, or seven days from the
  selected date), categories from `categories.json`, and attributes (free,
  family, ticket, registration). Filters are shown as chips with icon and
  label, each group has a reset link, and Escape closes the panel. The period
  is part of the URL (`#tag/2026-11-22`, `#wochenende/…`, `#woche/…`). If the
  period is empty, "Nächster Termin" (next event) jumps to the next matching
  day. Further filter groups can be added as additional `.fp-group` elements
  without widening the toolbar.
- **Category groups:** a category in `categories.json` may carry
  `"group": "<other category>"` (one level only), for example cinema, theatre,
  music and art in the group *Kultur* (culture). In the panel, the
  subcategories are framed behind their parent category. Selecting the parent
  selects the whole group (the subcategories are shown as implied); selecting
  a subcategory while the group is active narrows the selection to that
  subcategory. Each event still has exactly one category.
- **Time status for today:** events in progress are tinted green and labelled
  "Läuft" (in progress); finished events are visually de-emphasised
  (desaturated, dimmed, dashed border, also recognisable in dark mode). An
  event without an end time counts as in progress for two hours; all-day
  events for the whole day. When opened, the list scrolls to the first event
  that has not yet finished, and the status is refreshed every minute.
- **List grouped by day** (day headings stick below the toolbar).
  **Several days side by side:** as many columns as fit at a minimum of 260 px
  each, but no more than there are days in the period (tablet in portrait:
  weekend; landscape: four days; from about 1950 px: the whole week). Further
  days wrap to the next row, and the whole page scrolls. The page then grows
  to a maximum width of 1960 px and the cards become compact (time, "Läuft"
  and category on one line above the title). The detail and About pages stay
  narrow.
- **Search** via the magnifier icon. It covers all data, not just the selected
  period, and ignores accents (ß matches ss).
- **Search suggestions** from two characters: **Ort** (venue names and their
  individual words, for example "Brotfabrik" and "Kino" from "KINO
  Brotfabrik"), **Typ** (category; sets the category filter) and **Termin**
  (event title), each with the number of upcoming events. Supports arrow keys,
  Enter and Escape (ARIA combobox).
- **Event details** with a shareable URL (`/#<event-id>`), a map link
  (OpenStreetMap), "In Kalender" (download as .ics) and "Teilen" (share).
  Addresses in the description become links. External links (event, map,
  sources, addresses in descriptions) open in a new tab and carry the same
  icon as "Zur Veranstaltung" (to the event).
- **Saved events** ("Gemerkt"): every card has a star (grey = not saved,
  filled = saved) that saves the event directly from the list without opening
  the details. Saved events are stored only locally in the browser; no
  account is needed.
- **About page** with `about`, the list of sources, "Termin melden" (submit an
  event), legal notice and privacy policy.
- **PWA:** `build-site` generates `manifest.webmanifest`, and `sw.js` keeps the
  page and the most recently loaded events available offline. Provide
  `site/icon-192.png` and `site/icon-512.png` for installable icons.
- **Light and dark mode:** without a choice, the system setting applies. The
  switch in the header (moon/sun) sets the scheme and remembers it locally. If
  the choice matches the system setting again, it is cleared and the page
  follows the system once more. The scheme is set as
  `data-theme="dark"|"light"` on `<html>`. **Custom dark-mode rules in
  `site/css/theme.css`** must therefore be written as
  `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }`
  plus `[data-theme="dark"] { … }`; otherwise the system setting wins when the
  user has chosen light mode.
- **Sharing:** on mobile devices, "Teilen" opens the system share sheet (Web
  Share API, available only over HTTPS or on localhost); without the API, the
  link is copied to the clipboard. The app shares its link `/#<id>`; the
  static event pages (see below) have their own share button, which shares
  their address `termine/<id>.html` (with a preview in messengers).

### Static pages and SEO

These features are optional and **disabled by default**, as not every
instance needs SEO. Enable them with an environment variable (or the
corresponding flag of `build-site` or `serve`):

| Variable / flag | Generates |
|---|---|
| `OL_STATIC_PAGES=true` / `-static-pages` | `termine/`, today's events in the HTML of `/` |
| `OL_SITEMAP_GENERATOR=true` / `-sitemap` | `sitemap.xml`, `robots.txt` (only with `baseUrl`) |

Both together provide full SEO support; the sitemap on its own contains only
the start page. Canonical and Open Graph tags in `index.html` are always
present (for link previews when sharing).

```sh
docker run -d … -e OL_STATIC_PAGES=true -e OL_SITEMAP_GENERATOR=true ghcr.io/schreibtischhelden/openlitfass
```

With `OL_STATIC_PAGES`, `build-site` generates plain HTML alongside the app,
for search engines, link previews and visitors without JavaScript:

- `termine/index.html`: all upcoming events, grouped by day.
- `termine/<id>.html`: one page per event with title, description, Open Graph
  tags and a schema.org `Event` (JSON-LD, including the cancelled status).
- `sitemap.xml` and `robots.txt` (only with `baseUrl`, as sitemaps require
  absolute URLs; a custom `site/robots.txt` takes precedence).
- `sitemap.xml` is plain sitemaps.org XML without a stylesheet, so that every
  browser shows its XML tree view. (With a stylesheet reference, Firefox shows
  only text when XSLT is blocked, and XSLT is being removed from browsers.)
  The human-readable list is `termine/`. An XSL version is kept in the Git
  history (commit `ab98aff`); it could be revived later only with JavaScript,
  using <https://github.com/zcorpan/xslt_extension>.
- `index.html` (that is, `/`) already contains today's events in its HTML (or,
  if there are none today, those of the next day with events), plus a link to
  `termine/`. The app replaces this list once it has loaded. "Today" refers to
  the time of the last build: `serve` rebuilds after every fetch, so after
  midnight the list is updated only with the next fetch.

The templates live in `web/templates/` (Go `html/template`) and are not
deployed. Past events no longer get a page.

## A new instance in five steps

1. Copy `example-instance/` from this repository into a new, empty
   repository.
2. Fill in `instance.json`; adapt the legal notice and privacy policy in
   `site/`.
3. Add sources: copy a template in `sources/`, remove `.example` from the file
   name, and adjust the URL and mapping (syntax: [backend.md](backend.md)).
   How to find sources: [source-discovery.md](source-discovery.md).
4. Styling: `site/css/theme.css` (override the tokens from
   `web/css/tokens.css`) and, optionally, `site/logo.svg`.
5. Set the image path (`IMAGE`) in `.github/workflows/update-events.yml`, then
   push.

## Operation: one instance per container

The simplest way to run an instance, without CI or a separate web server, is
to mount the instance directory into the container:

```sh
docker run -d --name weissens --restart unless-stopped \
  -v /path/to/weissens.ee:/instance \
  -p 8080:8080 \
  ghcr.io/schreibtischhelden/openlitfass
```

The image's default command is `serve /instance`. It:

- serves the site on port 8080, from the existing data within seconds of
  starting;
- fetches all sources immediately and then every `OL_FETCH_INTERVAL` (default
  `6h`), and rebuilds the site. Each build goes into a new directory under
  `.openlitfass-serve/` and is switched live only once it is complete (a
  failed build leaves the previous version in place);
- writes to the instance directory in the same way as `fetch`: `data/`, the
  `status` field of each source, and deletion of expired inbox files;
- reports its state as JSON at `/healthz` (last fetch, number of events,
  failed sources, next fetch), which is also used by the image's
  `HEALTHCHECK`. `/metrics` serves Prometheus metrics (see below).

| Variable / flag | Default | Meaning |
|---|---|---|
| `OL_FETCH_INTERVAL` / `-interval` | `6h` | fetch interval; `0` = serve only |
| `OL_LISTEN_ADDR` / `-addr` | `:8080` | listen address |
| `OL_PUBLIC_DIR` / `-public` | `<instance>/.openlitfass-serve` | build directory |
| `OL_METRICS_ADDR` / `-metrics-addr` | empty | separate port for `/metrics`, e.g. `:9090` |
| `OL_STATIC_PAGES` / `-static-pages` | `false` | static event pages, see [Static pages and SEO](#static-pages-and-seo) |
| `OL_SITEMAP_GENERATOR` / `-sitemap` | `false` | `sitemap.xml` and `robots.txt` |
| `OL_WEB_DIR` / `-web` | `/opt/openlitfass/web` | core user interface (set in the image) |
| `OL_INSTANCE_DIR` / argument | `.` (image: `/instance`) | instance directory |

All environment variables start with `OL_` (openLitfass). Optional features
are disabled by default.

### Metrics (Prometheus)

`/metrics` provides metrics in the Prometheus text format (validated with
`promtool check metrics`). With `OL_METRICS_ADDR=:9090` they are served on a
separate port and are **not** reachable alongside the public site, which is
the recommended set-up. Without `OL_METRICS_ADDR`, `/metrics` is served on the
main port.

```sh
docker run -d … -p 8080:8080 -p 127.0.0.1:9090:9090 -e OL_METRICS_ADDR=:9090 ghcr.io/schreibtischhelden/openlitfass
```

| Metric | Type | Meaning |
|---|---|---|
| `openlitfass_info{version,instance}` | gauge | always 1; carries version and instance |
| `openlitfass_up` | gauge | 1 = the site is being served |
| `openlitfass_fetch_interval_seconds` | gauge | configured fetch interval |
| `openlitfass_last_fetch_timestamp_seconds` / `…_next_fetch_…` / `…_last_build_…` | gauge | points in time (Unix) |
| `openlitfass_fetch_runs_total{result}` | counter | fetch runs: `ok`, `partial` (some sources failed), `failed`, `nothing`, `error` |
| `openlitfass_builds_total{result}` | counter | site builds: `ok`, `failed` |
| `openlitfass_http_requests_total{code}` | counter | requests by status class (`2xx`, …) |
| `openlitfass_fetch_duration_seconds` | gauge | duration of the last fetch run |
| `openlitfass_source_up{source}` | gauge | 1 = the source's last fetch succeeded (taken from the `status` field, so also correct when CI does the fetching) |
| `openlitfass_source_last_success_timestamp_seconds{source}` | gauge | last success of the source |
| `openlitfass_source_fetch_duration_seconds{source}` | gauge | duration of the source's last fetch |
| `openlitfass_source_fetched_events{source}` | gauge | events from the source in the last run (before merging) |
| `openlitfass_source_carried_events{source}` | gauge | events carried over from the previous run because the source failed |
| `openlitfass_events` / `…_cancelled` / `…_merged` | gauge | published events: total, cancelled, merged from several sources |
| `openlitfass_events_by_source{source}` / `…_by_category{category}` | gauge | published events per source / category |

Scrape configuration:

```yaml
scrape_configs:
  - job_name: openlitfass
    static_configs:
      - targets: ["weissens-host:9090"]
```

Example alerts:

```yaml
groups:
  - name: openlitfass
    rules:
      - alert: OpenLitfassSourceDown
        expr: time() - openlitfass_source_last_success_timestamp_seconds > 86400
        labels: { severity: warning }
        annotations: { summary: "Source {{ $labels.source }} has not succeeded for more than a day" }
      - alert: OpenLitfassNoFetch
        expr: time() - openlitfass_last_fetch_timestamp_seconds > 2 * openlitfass_fetch_interval_seconds and openlitfass_fetch_interval_seconds > 0
        labels: { severity: warning }
        annotations: { summary: "{{ $labels.instance }}: no fetch for two intervals" }
      - alert: OpenLitfassDown
        expr: openlitfass_up == 0
        for: 5m
        labels: { severity: critical }
```

The version reported by the image is set by `image.yml` (build argument
`VERSION`); locally built images report `dev`.

**HTTPS and custom domains:** put a reverse proxy in front (Caddy, Traefik,
nginx). `serve` sets suitable cache headers (data, the start page and the
service worker are never cached).

If you also want to version the data in the instance's Git repository, use
the CI workflow `update-events.yml` instead (or in addition); with
`OL_FETCH_INTERVAL=0`, `serve` then only serves the site.

## Testing locally

See [Running locally](backend.md#running-locally), using the path of your own
instance instead of `example-instance`.

## Updating the core

Instances pull the image `…/openlitfass:latest`. For reproducible runs, pin a
commit tag instead (`…/openlitfass:sha-<short>`) and upgrade deliberately.

## Limitations

The user interface texts (filter labels, empty state, …) are currently in
German only; they are collected in `STR` at the top of `web/js/app.js`.
Multiple languages and instance-specific texts are not yet supported.
